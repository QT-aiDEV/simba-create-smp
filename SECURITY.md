# Security Policy

## Reporting a vulnerability

Do not open a public issue for credential leaks, remote-code-execution concerns, server access problems, private player data, or other exploitable vulnerabilities.

Use GitHub's private vulnerability reporting feature when it is enabled for this repository. If that feature is unavailable, contact the repository owner privately through their GitHub profile and share only the minimum information needed to establish a secure channel.

Never include passwords, tokens, private keys, server addresses, player IPs, world archives, or full production logs in a public report.

## Supported versions

Security fixes are normally applied to the latest CurseForge release. Older releases may be asked to upgrade before receiving support.
